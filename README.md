# 项目图谱 · Codex 工作台

Vue 前端和 Go 本地服务，用卡片查看本地项目的组织方式和功能入口。

## 功能

- 本地项目登记：从左侧「+」填写目录，保存到本地项目列表。
- 通用项目规划：每个项目都有「项目规划」页，进入时建立递归源码清单，并复用已有 App 界面与代码映射。点击「完整分析项目」，通过本机 Codex App Server 创建独立的只读规划会话，按目录模块分批分析文件，再核对跨模块链路。同一目标项目、工作台目录和技能版本下继续分析会复用会话，跳过已分析且内容未变化的文件。
- 全景链路：页面／功能入口连接 UI 代码、客户端请求、后端接口、中间件、业务组件和存储。可看全局或所选节点的多级下游关系，共享节点只保留一份；已有截图直接预览，无截图的页面明确提示待补。关系来源区分项目映射和 Codex 分析，源码位置可核对不代表运行路径已经实测。
- 分析覆盖：按模块列出已分析、待分析及变更文件，可单独重分析某个模块。每批档案与文件覆盖一并保存；停止或失败后，前面已完成的批次保留。最后单独核对跨模块关系，未完成时明确标注。重新扫描识别新增、删除和修改的文件；覆盖率针对上次扫描版本，不代表所有功能已验收。
- 卡片开发任务：选择卡片，打开「规划与任务」，填写要求后发起独立的开发会话。可以继续同一卡片的历史开发会话或停止当前任务。开发会话允许修改项目目录，规划会话只读；回合结束不代表功能已验收。一个项目同时执行一个任务，全服务最多三个。
- 档案与追溯：规划结果和成功状态一并写入 SQLite，失败不会覆盖上一版档案。可下载历史 JSON 版本；源码位置限定在项目目录并核验定位文字，文件变化时显示分析已过期。原始目录扫描、Codex 分析与待确认事项分别标注。
- App 界面：识别为原生 App 后，可切换到「App 界面」查看原有分组链路；项目默认进入「项目规划」的全景视图。可读取 `screenshots/` 或 `docs/screenshots/` 中的截图。项目根目录的 `.codex-app-ui.json` 可按导航分组，标记主页面，并关联截图、SwiftUI 源码路径及可试玩 Demo。主界面截图直接通过粒子曲线连接清单中的功能卡片；切换主界面可查看对应分组，点击卡片打开界面详情和关联 Demo。「全部界面」可浏览所有截图并跳转到分组；每个页面可保存浅色、深色及不同交互状态的截图，点击卡片查看原图。
- 项目 Demo：从 `demos/<名称>/index.html` 识别可试玩的本地网页。也识别 `demo/`、`prototypes/`、`docs/demos/` 与 `stitch_app/`；早期 Stitch 稿以同目录的 `screen.png` 展示。试玩页面在隔离框架中打开，依赖的脚本和素材可随 Demo 保存。
- 识别详情：从项目页上方进入，查看架构、内容和功能卡片。
- 项目架构：从构建配置和常见目录识别前端、后端、客户端及技术栈。
- 项目内容：列出项目根目录的主要源码、文档、测试和配置，可展开更多目录项。
- 功能识别：优先读取模块配置和 README 功能清单，也能从常见页面目录、功能目录及 Go 接口声明识别入口。卡片显示识别来源。

## 界面识别与真实预览

「项目规划」和「App 界面」共用同一份页面节点与预览关联。Codex 识别出 `page` 节点后，即使没有图片也显示页面卡片，可从界面直接跳到对应功能链路；已有 `.codex-app-ui.json` 分组与源码映射继续保留。

预览素材独立于源码清单：扫描 `previews/`、`screenshots/`、Demo 目录，以及 Markdown 文档明确引用的项目内图片，不把素材数量计入源码分析覆盖。完整分析会把素材路径和文档引用交给 Codex；模型输出的关联必须指向已有页面、真实项目图片和可核对的源码／文档依据。无法确认的关联留待补充，不影响已完成的源码批次。

- **完整界面**：包含页面控件的 App 或模拟器截图。
- **渲染输出**：Metal／GPU 导出、视觉海报等，不计为完整界面。
- **历史参考**：旧方案、概念稿或尚不能确认当前实现的图片。

在页面卡片点击「关联预览」，可搜索项目素材、查看文档引用、指定类型、关联或移除。也可上传运行中的原生 App／模拟器截图（PNG/JPEG，最多8MiB、4000万像素，每项目最多120张）。上传图片和手动关联保存在工作台 SQLite，不写入被分析项目；相同图片复用存储。手动关联优先于模型输出，移除关联不删除共享图片。项目图片变化后会提示重新核对。

界面覆盖单独显示「已识别页面／状态数、已关联预览数、完整界面截图数」。有预览不代表当前运行状态，代码覆盖完成也不代表所有交互状态均已采集。工作台不会自动启动任意项目；当前版本支持读取已有素材及上传真实运行截图。原生画面无法直接在网页运行时，可保留截图状态并追踪其代码链路。

Xcode 的 `.pbxproj`、`.xcscheme`、`.xcworkspacedata`、`.xcconfig`、`.entitlements` 纳入源码分析与定位；`.app`、Framework、Archive、Build 等产物排除，避免重复统计打包代码。修改扫描支持后继续完整分析会重建清单，保留未变化文件的分析结果。

## 分析会话与通用技能

分析会话的 `cwd` 属于工作台，被分析项目的 `targetRoot` 单独传入。每个目标项目各有一个「工作台分析 · 项目名」会话；开发任务仍在目标项目目录执行。旧版归属目标项目的分析会话和档案保留，升级后第一次分析创建工作台会话，不把旧会话伪装成已迁移。会话目录、目标路径、技能版本和实际适配器可在「分析上下文」及任务历史查看。

技能源文件为 `server/skills/project-analyzer/SKILL.md`，按源码与技术栈选择 Swift/Xcode、Web、Go 参考规则。其他技术栈使用通用源码证据流程，专用适配能力不足时如实记录。构建时嵌入技能；每轮开始保存至 `.data/analysis-skills/<SHA-256>/project-analyzer/`，通过 Codex 的 `skill` 输入显式调用，并附上本轮启用的规则。后续批次校验快照摘要，内容变化即停止。源码、扫描规则或技能调整后需重新构建服务；编辑快照不能发布新版本。

技能或启用适配器变化时，会创建新的分析会话并重新复核文件覆盖；已有图谱、人工预览和历史档案保留。覆盖清单中的旧结果不会冒充新技能版本的验收。

Codex 可返回有文件读取证据的 `capabilityGaps`，区分适配器、扫描器和预览缺口。服务核对源码位置，记录建议、验证方法、来源任务和技能版本，按项目保存并在页面显示为「待验证」。业务待办仍放项目待确认事项。分析进程不会修改全局技能或目标项目的 AGENTS.md。

改进流程：从已记录缺口复现问题 → 修改技能规则及必要的扫描器 → 用隔离样例和相关回归检查验证 → 更新 SKILL.md 的 `metadata.version` → 重建并发布工作台。新版本在下一轮使用，不在正在执行的分析里自动切换。技能基础校验可用 skill-creator 的 `quick_validate.py`；后端 `go test ./...` 覆盖迁移、隔离、读取证据及快照完整性。需要验证本机真实 Codex 时，在 `server/` 设置 `PROJECT_MAP_REAL_CODEX=/绝对路径/codex` 并运行 `go test -run '^TestAnalysisSkillRealCodex$' -v -timeout 5m`，使用临时项目和数据库，结束后归档验证会话。

## App 源码关系

功能卡片旁的「代码关系」展示已定位的源码及后端关系，默认连出接口、中间件、处理函数、组件和数据存储，不需要逐个展开依赖。卡片标明代码分类；共用节点只显示一次。点文件名可看对应行附近的源码，接口卡片还可切换到客户端请求和 Go 路由注册的片段。

连线标明「进入鉴权」「鉴权通过」「调用」「读取」「写入」等关系，点击连线文字可查看源码依据。悬停、键盘聚焦或点选卡片时，高亮该卡片涉及的路径，并沿路径播放一次粒子流光。共用中间件不会让一个处理函数的高亮混入其他接口。动画表达选中关系，不代表真实请求正在执行。支持减少动态效果、图谱缩放和横向滚动；窄屏保留全部关系。

默认用 `.codex-app-ui.json` 的 `source` 定位 UI 文件。可在被登记项目的根目录添加 `.codex-app-code.json` 来细化关系：

- `features`：以 `分组标题/界面标题` 对应 `nodes` 里的节点 ID 列表。
- `nodes`：每个节点填写 `title`、`kind`、项目相对 `file` 和用于定位行号的 `match`（源码中的一行文字片段）。可用 `evidence` 记录其他 `{file, match}` 位置。
- `后端接口` 节点要提供客户端请求与服务器路由注册两处依据。节点的 `links` 描述多级关系，每项填写 `from`、`to`（引用 `nodes` 中的 ID）、`label` 和 `evidence: [{file, match}]`。例如接口 → 鉴权 → 处理函数 → 业务组件，鉴权还可连到会话数据表。共享组件引用同一个节点 ID。
- 每条新关系必须有可定位的源码依据。返回的图只包含从该接口可达的有效节点和关系；缺失位置、循环和超出限制的部分不会成为可访问源码入口。旧配置的 `uses` 仍显示为「依赖」，不推断其执行顺序。

四时的映射保存在自己的 `.codex-app-code.json`。未补充的关系不会按文件名猜测，也不表示功能一定没有后端。

关系图的数据合并、共享节点路径隔离及布局检查可运行 `pnpm test`（Node.js 22.12+）；后端源码校验测试在 `server/` 运行 `go test ./...`。

## Codex 会话与状态粒子

项目规划和 App 界面的会话面板显示本机 Codex 用户消息、回复和工具操作，可按会话筛选、展开命令结果及文件路径，并从精确定位的事件跳到功能代码卡片。跨项目会话只有直接操作当前项目文件的工具事件才会显示，其他项目的对话不混入。不会读取或展示模型思考内容。

工作台创建的任务直接接收 App Server 的真实回合与工具事件，并和本地历史去重。通用图谱沿「项目／选中功能 → 实际涉及的文件」播放状态粒子，功能关系保留静态依据；文件级事件只说明文件被操作。精确函数级关联目前主要支持 Go 和 Swift，其他项目仍可展示文件级状态。App UI 展示继续依赖项目中的截图、Demo 或 UI 配置，规划不会自动运行任意项目或凭空生成完整应用界面。

- 蓝色表示读取，紫色表示修改，琥珀色表示测试，红色表示失败。正在执行的精确操作持续沿目标卡片的直接入线流动，结束或失败的新事件只播放一次。历史加载、重复快照和断线重连不回放旧事件。
- 函数定位核对声明、改动文本及当前源码；只有文件路径、过期行号或无法验证的内容显示为「涉及文件」，不会点亮同文件所有功能。没有对应图谱的操作仍保留在事件列表。这里只反映 Codex 开发操作；源码依赖连线不表示 App 请求实际执行过所有下游组件。
- 数据源不可用、读取降级或连接失效时停止实时粒子，保留历史。残留运行态按回合状态和更新时间变为中断或待确认，不把“会话结束”当成功能完成。系统减少动态效果设置会保留文字状态并关闭粒子动画。

本地服务只读 `-codex-home`（默认 `~/.codex`）下的 `state_5.sqlite`、`thread_history_1.sqlite`，并用 `sessions/`、`archived_sessions/` 的 JSONL 补充缺失的本项目历史。这些本地格式有版本差异，解析失败会显示读取状态。当前采用有界近期窗口：SQLite 最近 12 个本项目会话、过去 24 小时最近 24 个其他项目候选会话，每会话近期 90 条事件；JSONL 最多补充 6 个本项目会话，每文件最多读末尾 4 MiB。页面约每 2 秒更新，保留近期事件，不是完整历史归档。JSONL 补充来源的补丁目前只提供文件级关联。

## 运行

需要 Node.js 22.12 或以上、pnpm、Go 1.24 或以上以及可用的 C 编译器（SQLite 驱动需要 CGO）。以下命令在项目根目录运行。

创建规划和开发任务还需要已登录且支持 App Server 协议的本机 Codex CLI（本次用 `0.169.0-alpha.11.1` 验证）。可用 `-codex-bin /绝对路径/codex` 指定可执行文件；CLI 不可用时，仍可浏览目录扫描和已保存档案。模型连接或登录失败会显示在任务结果中，不会生成虚假的规划成功状态。

```sh
pnpm install
pnpm build
mkdir -p bin
(cd server && go build -o ../bin/project-map .)
./bin/project-map -workspace "$PWD"
```

打开 <http://127.0.0.1:4399/>。`-workspace` 指定启动时登记的目录；`-analysis-workspace` 指定分析会话所属的工作台目录，默认是启动服务时的当前目录。点击左栏的「+」可登记其他目录，项目列表保存到本地 SQLite。按 `Ctrl+C` 停止服务。

规划档案、会话标识和任务事件保存在 `-data` 指定的本地目录（默认 `.data/tasks.sqlite`）。正常停止服务会取消本服务正在执行的任务；异常退出后重启会把残留任务标记为中断，已有文件变更仍需核对。

完整分析范围为可读取的源码、配置和文档，依赖、构建产物、隐藏文件、凭据、二进制素材及超大文件会在扫描排除范围中说明。扫描最多记录 10000 个文件、访问 100000 个目录项；达到上限会明确提示清单被截断。分析每批最多 12 个文件并按内容大小拆分，整个任务最长 4 小时，可停止后继续；开发任务维持 30 分钟上限。任务会使用本机 Codex 已配置的模型额度。
